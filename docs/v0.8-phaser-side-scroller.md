# v0.8 Phaser side-scroller refactor

This release replaces the previous React/CSS pseudo-pixel world with a Phaser 2D side-scroller scene.

## Goals

- Keep React for app UI, settings, dictionary editing, story, training cards, and fight overlays.
- Use Phaser only for the animated world: parallax layers, sprite sheets, encounters, hero actions, and monsters.
- Make the side-scroller visually stable: objects are anchored to ground or background layers instead of floating on a pseudo-perspective path.
- Make testing easier with a debug bypass mode in Settings.
- Make training stricter: a failed practice session does not count and does not award attribute progress.
- Make fights numerically clear: enemies cannot die before question 10, but from question 10 onward enemy HP <= 0 ends the fight immediately.

## Renderer layout

The active renderer is:

```text
apps/web/src/components/PhaserWorld.tsx
```

The Phaser scene has a fixed internal resolution of 960 x 540 and scales to the available screen using Phaser's FIT scale mode. React places the training/fight panels below the game scene, not on top of it.

## Pixel assets

The placeholder pixel assets live in:

```text
apps/web/public/assets/pixel/
```

They are generated by:

```text
tools/generate-pixel-assets.py
```

The generated placeholders are marked CC0/public domain in:

```text
apps/web/public/assets/pixel/LICENSE-PIXEL-ASSETS.md
```

These can later be replaced by a proper CC0/permissive pixel-art pack. Keep third-party licenses and attribution files next to the imported assets.

## Training completion rule

The default training rule is in the language pack:

```text
content-packs/hy-eastern-it/tasks.yaml
```

```yaml
questions_per_training: 10
training_completion:
  max_mistakes: 3
```

If the child makes more than `max_mistakes`, the practice session is discarded for progression: it does not count as a completed training session and does not increase attributes or coins. Debug bypass ignores this restriction for testing.

## Fight balancing

Level caps are intentionally exponential in:

```text
content-packs/hy-eastern-it/levels.yaml
```

Enemy energy is configured in:

```text
content-packs/hy-eastern-it/enemies.yaml
```

The app also enforces this invariant:

```text
effective enemy HP >= level stat cap * 10
```

This means a maxed hero still needs at least 10 correct hits to beat the monster. If the hero is undertrained, damage is lower and the fight lasts more questions. Too many mistakes usually cause the hero to run out of energy before the enemy is defeated.

## Debug bypass mode

Settings contains two debug options:

- Debug mode: shows renderer and fight math information.
- Debug bypass mode: bypasses fight gates, unlocks shop items, and ignores training completion restrictions.

Debug bypass is intended only for development/testing.
