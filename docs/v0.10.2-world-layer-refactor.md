# v0.10.2 world layer refactor

This release refactors the active Phaser renderer so scenery objects are no longer positioned randomly around the hero walk line.

## Main renderer files

- `apps/web/src/components/PhaserWorld.tsx` contains the Phaser scene lifecycle, sprite loading, hero/enemy/station animation, object pooling, and encounter positioning.
- `apps/web/src/worldConfig.ts` contains the world geometry, depth ordering, parallax tile-layer settings, scenery-layer settings, and object frame definitions.

## Object placement model

Objects now belong to explicit scenery layers:

- `background`: trees, cottages, caves, and bushes. These are anchored to the village/near-background layer and drawn behind the hero.
- `pathBack`: logs, signs, rocks, stumps, and bushes. These are anchored to the back edge of the walkable path and still drawn behind the hero.
- `foreground`: grass, flowers, small rocks, and mushrooms. These are anchored near the front edge of the path and drawn in front of the hero's feet.

Each object layer has its own speed, depth, base Y coordinate, spacing range, and encounter-avoidance radius. Objects recycle from the right only after leaving the left edge, and the next X position is based on the rightmost object in the same layer so objects do not reappear in the middle of the screen.

## Parallax layers

The renderer now uses these parallax layers:

1. fixed sky
2. mountains
3. hills
4. forest
5. village
6. broad ground/path strip
7. background/pathBack object layers
8. hero/enemy/station layer
9. foreground object layer

The new `bg-hills.png` layer sits in front of the mountains, which reduces the cutout/flat-background feel.

## Hero additions

The Phaser renderer now supports layered hero attachments:

- sword overlay
- shield overlay
- armor overlay
- dragon companion

The overlays use frame-aligned sprite sheets, so they follow the same animation frame as the base hero without needing separate hero+sword, hero+shield, hero+armor combinations.

The overlays are shown when matching inventory items are owned:

- sword/wand item IDs show the sword overlay
- shield/cape item IDs show the shield overlay
- armor/helmet/mask/boots/sneakers item IDs show the armor overlay
- pet/dragon item IDs show the dragon companion

The intentionally supported set is small: sword, shield, armor, and companion. Keeping this list short avoids a combinatorial sprite explosion while still making shop rewards visible.

## Assets

New or updated source assets live in:

```text
asset-packs/cc0-pixel-v10/
```

The runtime copy is generated with:

```bash
npm run assets:sync
```

The procedural CC0 placeholder pack can be regenerated with:

```bash
npm run assets:generate-parallax
```

That command rewrites the source asset pack before syncing it, so do not use it after hand-editing the PNGs unless you intentionally want to regenerate the placeholder art.

Do not edit `apps/web/public/assets/pixel/` directly unless you also copy those edits back into the asset pack.
