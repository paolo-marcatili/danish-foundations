# Audio and content contributions

This MVP is designed for low-resource and community languages. A language pack should work even when commercial speech services are unavailable.

## Audio priority in the app

The default setting is **human voices only**. In that mode, the app plays approved or pending human recordings only. Automated audio and browser TTS stay silent so children are not trained on poor synthetic pronunciation by accident.

In Settings, switch **Lesson audio** to **Human + automatic voices** to use automatic preview audio. In that mode, the app chooses audio in this order:

1. approved human recordings
2. any human recordings that still need review
3. browser text-to-speech, but only if the browser reports a matching Armenian voice
4. local automated preview `.wav` audio generated by eSpeak/eSpeak NG
5. browser speech synthesis fallback

Community recordings automatically replace automated preview audio in gameplay without deleting the automated files.

## Add audio through the in-app admin panel

1. Run the app with `npm run dev`.
2. Open Settings, then press **Edit dictionary**.
3. Click an existing word/sentence in the vocabulary list, or create a new one.
4. Enter Armenian text, Italian translation, transliteration, complexity, and controlled semantic tags.
5. Press **Record**, speak, then press **Stop**.
6. With **Auto-save after Stop** enabled, the recording is merged into the browser/device copy immediately.
7. Use **Export pack** or **Download contribution** when you want to share changes with the repository/community.

If the Armenian word or sentence already exists, the merge appends the new audio entry instead of overwriting existing audio.

## Community-friendly merge workflow

A normal browser cannot silently write to a Git checkout on disk. The in-page merge therefore updates the local browser copy immediately, then lets you export JSON for sharing.

Recommended community flow:

```text
Record or edit in the app
  -> Save here for immediate play
  -> Export contribution JSON or local pack JSON
  -> Open a pull request, upload to a review form, or send to a maintainer
  -> Maintainer imports/merges, validates, and publishes the next pack version
```

For a larger community, the next step should be a small self-hosted backend that accepts contribution JSON, shows review status, and writes approved changes to the content-pack repository through a bot account.

## Merge a contribution into the repository

From the repository root:

```bash
npm run content:merge -- ./my-contribution.json
npm run validate:content
```

The browser merge and terminal merge are duplicate-safe:

- If the Armenian word or sentence already exists, the script appends audio to the existing entry.
- If it does not exist, the script creates a new item marked `needs_native_speaker_review`.
- Existing audio is not overwritten.
- If no human audio is included, the entry gets browser-TTS fallback metadata so it can be played when automatic audio is enabled.
- Community audio is written to both:
  - `content-packs/hy-eastern-it/audio/human/...`
  - `apps/web/public/content-packs/hy-eastern-it/audio/human/...`

The second location is needed because the Vite web app serves static runtime audio from `apps/web/public`.

## Generate automated preview audio

This repository includes automated preview audio generated with an Armenian eSpeak/eSpeak NG voice. To regenerate it locally:

```bash
npm run content:auto-audio
```

The script first looks for `espeak-ng`, then `espeak`. You can tune the voice from the command line:

```bash
HLC_ESPEAK_VOICE=hy HLC_ESPEAK_SPEED=128 HLC_ESPEAK_PITCH=45 npm run content:auto-audio
```

Automated audio is only a bootstrap. It should be reviewed and eventually replaced by human recordings.

## Add or edit vocabulary manually

The canonical word list is JSONL:

```text
content-packs/hy-eastern-it/dictionary/words.jsonl
```

One JSON object per line:

```json
{"id":"hy_example","concept":"example","target":"օրինակ","translation":"esempio","translations":{"it":"esempio"},"transliteration":"orinak","ipa":"","difficulty":1,"complexity":1,"tags":["community"],"audio":[],"hard_distractor_ids":[],"review_status":"needs_native_speaker_review"}
```

Sentence-order exercises live in:

```text
content-packs/hy-eastern-it/dictionary/sentences.jsonl
```

Letters live in:

```text
content-packs/hy-eastern-it/dictionary/letters.jsonl
```

Use stable IDs and append audio entries instead of replacing them. That makes pull requests easier to merge.

## Suggested review process

1. Contributor adds a word/sentence and audio.
2. Native speaker checks spelling, dialect/variety, translation, and appropriateness for children.
3. A second reviewer approves when possible.
4. Change `review_status` to `approved` for the content and the audio.
