# v0.11.7 — Camera-following labyrinth and canonical walls

This release changes the labyrinth renderer without changing maze generation,
questions, rewards, hearts, or persistence.

## Camera-following viewport

The logical maze remains 7 × 7, but the renderer follows the hero instead of
shrinking the entire maze into one screen.

- Desktop/tablet: approximately a 5 × 5 region.
- Mobile: approximately a 3 × 3 region.
- The camera is clamped at map boundaries.
- A compact optional minimap shows explored rooms and the current hero cell.

## Stable wall topology

`getLabyrinthWallEdges()` builds every closed maze edge exactly once. Wall
ownership no longer changes when fog is revealed. Internal walls are owned by
the south/east cell through its north or west edge; south and east edges are
added only on the map boundary.

`validateLabyrinthTopology()` checks:

- reciprocal passages;
- map connectivity;
- duplicate wall IDs;
- expected canonical wall count.

The renderer depth-sorts walls by their actual isometric edge midpoint, placing
a shared wall between the rear room and the front room.

## Wall graphics

The four 256 × 192 wall files now contain low, single-edge guides. A procedural
dark line is rendered beneath every wall image for clear maze demarcation.

Regenerate the guides with:

```bash
npm run assets:generate-labyrinth-walls
```

## Navigation

The labyrinth supports:

- tapping an adjacent room;
- the on-screen direction pad;
- arrow keys;
- WASD keys.

Keyboard movement is disabled while a question is active or while the session
is locked.

## Responsive layout

The labyrinth uses the remaining app viewport instead of extending the page.
On desktop, questions open beside the map. On mobile, the map remains visible at
the top and the question panel scrolls internally beneath it.

The normal Phaser side-scroller now keeps a fixed 16:9 aspect ratio when session
panels appear, preventing its viewport from changing height between modes.
