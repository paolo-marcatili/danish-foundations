# v0.11.4 — Labyrinth visual and encounter refresh

This release replaces the schematic grid/emoji labyrinth presentation with a warm isometric fantasy-ruins renderer driven by replaceable PNG assets. It also adds traps and immediate exploration events while retaining the existing question budget, fog of war, autosave, hearts and reward rules.

## Gameplay additions

- Three trap encounters per run by default. A failed trap question removes the pack-configured number of hearts.
- Two hidden coin caches. Coins are provisional and are only kept when the expedition succeeds.
- One healing fountain that restores one heart up to the run maximum.
- One reveal obelisk that uncovers connected cells within the configured radius.
- Three illustrated monster variants and a separate final guardian scene.
- Decorative ruins, roots, mushrooms, ferns and fireflies on some empty explored cells.
- Connected path overlays selected from each cell's north/east/south/west exit mask, so the explored map reads as a route network rather than a checkerboard.

The defaults are editable in `content-packs/hy-eastern-it/labyrinths.yaml` under `events`.

## Renderer changes

The labyrinth remains a React/SVG isometric map, but SVG primitives are now used only for layout and interaction. Floors, routes, walls, fog, tokens, events and encounter scenery are image assets in:

```text
asset-packs/cc0-pixel-v10/labyrinth/
```

The runtime mirror is:

```text
apps/web/public/assets/pixel/labyrinth/
```

Edit only the source asset-pack folder, then run:

```bash
npm run assets:sync
```

Do not run the placeholder generator after manual/image-model edits unless you intentionally want to reset the complete labyrinth asset set.

## Placeholder generation

```bash
npm run assets:generate-labyrinth-placeholders
```

This regenerates all clean guide images at their required dimensions and then syncs them to the web app. The guide artwork is intentionally simple and should be treated as an image-to-image input.
